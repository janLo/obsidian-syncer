# Obsidian Sync Server

A headless sync hub running as a Docker container that integrates:
- Obsidian Sync (official `obsidian-headless` client)
- Nextcloud Sync (`nextcloudcmd` client)
- Google Keep (pulling notes via `gkeepapi`)

## The Sync Process

The server runs in daemon mode and orchestrates three distinct synchronization tasks for each of your configured "sync sets" (vaults). 

**Continuous Sync:**
*   **Obsidian Sync:** The official `obsidian-headless` client is launched as a persistent background process. It runs continuously, observing your vault directory and pushing/pulling changes in real-time with the Obsidian Sync servers.

**Periodic Sync (Every 5 minutes by default):**
Every sync interval, the main Python daemon wakes up and performs the following sequence for each vault:
1.  **Keep Alive:** It verifies the Obsidian Sync background process is still running and healthy, restarting it if necessary.
2.  **Google Keep Pull:** It connects to Google Keep via `gkeepapi`. It searches for active notes matching your configured `tags` (while ignoring any `ignore_tags`). It converts matching notes to Markdown and saves them into the designated `target_folder` within your vault. If configured, it applies a `mark_synced_tag` to the original Keep note so it isn't pulled repeatedly.
3.  **Nextcloud Sync:** It invokes `nextcloudcmd` to synchronize your local vault directory with your remote Nextcloud server. This ensures all your Obsidian notes (and your newly imported Keep notes) are backed up to Nextcloud.

*Conflicts:* In this architecture, Obsidian is considered the authoritative source of truth. To prevent sync loops and duplicate files, any conflict files generated by Nextcloud (`_conflict-*`) are automatically deleted during the Nextcloud sync phase. Obsidian's own conflict resolution strategy will handle any underlying discrepancies.
## Setup Configuration

Create a `config.yaml` file mapping your sets:

```yaml
sync_sets:
  - name: "my_vault"
    local_dir: "/vaults/my_vault"
    obsidian:
      enabled: true
    nextcloud:
      enabled: true
      url: "https://nextcloud.example.com"
      user: "${NC_USER}"
      password: "${NC_PASSWORD}"
      remote_folder: "/Obsidian/my_vault"
    keep:
      enabled: true
      username: "${KEEP_USER}"
      password: "${KEEP_PASSWORD}" # Use a Master Token (starts with aas_et/...)
      tags: ["Gemini"]
      target_folder: "/vaults/my_vault/KeepNotes"
```

## Authentication Guidelines

### Obsidian Headless
The `obsidian-headless` tool requires an active Obsidian Sync subscription.
To authenticate, you should run the container interactively once:

1. Open a terminal in the container: `docker exec -it obsidian-syncer bash`
2. Run `ob login` and follow the prompts.
3. Link the vault with `ob sync-setup --vault "YourRemoteVaultName" --path /vaults/my_vault`.
4. Restart the container so the Python daemon picks up the new sync process.

### Google Keep
For reliable syncing, standard passwords and App Passwords are no longer supported for continuous syncing, as Google's security blocks frequent login requests. You **MUST** use a **Master Token**.

To generate a Master Token, run the included helper script which supports two authentication flows: the App Password flow and the OAuth Cookie flow.

```bash
uv run scripts/get_keep_token.py
```

Follow the prompts to generate your Master Token (starts with `aas_et/`). Use this Master Token as your `KEEP_PASSWORD` environment variable. For detailed instructions on the authentication flows, please refer to the [Authentication Guidelines](docs/authentication.md).

### Nextcloud
Pass your Nextcloud credentials via environment variables (`NC_USER` and `NC_PASSWORD`). The configuration file will dynamically expand these variables to prevent hardcoding secrets.

## Running with Docker

Run the container using a bind mount for the configuration, vaults, and obsidian configuration directory:

```bash
docker run -d \
  --name obsidian-syncer \
  -v $(pwd)/config.yaml:/config.yaml \
  -v $(pwd)/vaults:/vaults \
  -v $(pwd)/ob-config:/root/.config \
  -e NC_USER=... \
  -e NC_PASSWORD=... \
  -e KEEP_USER=... \
  -e KEEP_PASSWORD=... \
  ghcr.io/janlo/obsidian-syncer:latest
```

## Running with Docker Compose

For a more persistent setup, you can use Docker Compose. An example `docker-compose.yml` is included in the repository:

```yaml
services:
  obsidian-syncer:
    image: ghcr.io/janlo/obsidian-syncer:latest
    container_name: obsidian-syncer
    restart: unless-stopped
    volumes:
      - ./config.yaml:/config.yaml:ro
      - ./vaults:/vaults
      - ./ob-config:/root/.config
    environment:
      - NC_USER=${NC_USER}
      - NC_PASSWORD=${NC_PASSWORD}
      - KEEP_USER=${KEEP_USER}
      - KEEP_PASSWORD=${KEEP_PASSWORD}
```

Run the container in the background using:

```bash
docker compose up -d
```
